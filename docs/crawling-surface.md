# Guided crawling and result coverage — Phase 3 extension

**Mode: Operate.** Existing GPUI working-desk proposal, not a replacement visual
world. Inherits `DESIGN.md` and shared native controls. Human visual review and
meaningful native rendering/input remain pending; no screenshot approval is implied.

## Direction contract

**Thesis:** make the exact page/profile inventory understandable before any
baseline capture. A website is not a screenshot count, and missing evidence is
not an unchanged result.

**Own-world:** retain the bright ground, teal actions, legible installed UI type,
flat list rules and bounded form width. No web mock, developer JSON editor,
invented percentage or decorative dashboard.

**Story:** addresses → scope → screen sizes → Find pages → inspect coverage and
include/exclude → capture → explicitly activate. Checks stay on the active fixed
inventory. Replacement discovery is a separate deliberate action.

**First viewport:** setup starts with recognizable project/name/list fields,
approved websites, list/link mode and everyday boundaries. Screen-size and speed
choices follow; advanced dimensions/depth/concurrency stay behind a disclosure.
Results starts with project actions and an honest intended-page/screenshot
summary, followed by a 300px virtualized list and selected evidence viewer.

**Form:** a precisely scoped extension of the existing shell, not a new concept
round. The signature interaction is reviewing a real bounded inventory before
capture, then filtering the same keyed coverage without changing evidence.
Keyboard previous/next target and explicit include/exclude actions complement
click selection. Search changes visibility, never coverage.

**Finish:** native rendered review is **pending**, not replaced by simulated GPUI
or backend tests. The serial independent verifier receives current sources,
actual worker captures, source/control tests and the inherited visual proposal.
No nested finish-review agent was spawned, per the user's scope restriction.
