## Implementation

- `ui/theme.rs` supplies matching semantic light/dark palettes. Dark mode uses
  layered blue-charcoal surfaces, light blue-gray ink, mint/teal actions and
  distinct readable warning/error colors. Separate on-accent, selected-navigation
  ink and shadow roles prevent white workspace assumptions leaking into dark mode.
- Shared actions, text fields, selectors, scrolling, menus, inspectors, loading,
  failure states and dialogs resolve the palette. About uses the existing logo
  intended for its current background. No new dependency, motion or shipping asset.
- `appearance_ux.rs` subscribes to GPUI window-appearance notifications, including
  vibrant variants. System follows those changes; either explicit override ignores
  them. Full-window refresh invalidates cached child controls and prompts.
- `core/appearance.rs` deliberately separates app appearance from website capture
  profiles. Switching the app theme never changes a project's website-theme choice.
- `storage/preferences.rs` keeps a small, validated, atomically replaced
  `app-preferences.json` in the local app-data directory, outside project artifacts
  and baseline ZIPs. Absent preferences default to System; unreadable settings show
  an honest fallback and failed writes keep the session choice with retry guidance.
- `appearance.rs` owns file I/O on a separate serial worker. Rapid choices coalesce
  without stale replies overwriting newer intent; shutdown flushes the last choice
  after the UI exits. Startup resolves the remembered override before showing the
  window, without doing file I/O in a UI callback.
- Choices reuse native shared radio controls, follow painted keyboard order and
  reveal within the real settings scroller. Hidden, disabled or modal-occluded
  choices do not activate. No capture, baseline save or review operation is queued.
