# Workflow revamp — approved brief

The user selected **Clear wayfinding** on 2026-10-11 and confirmed the workflow
below. This is the implementation brief, not a claim of completed native or
release qualification. The application remains local, native Rust/GPUI, and
intended primarily for somewhat tech-savvy non-developers.

## First baseline

1. Name the project and establish its starting website addresses.
2. Establish access: public pages, or interactive login and consent in the managed
   browser. Environment sessions remain separate and securely stored, or explicitly
   limited to the current app session.
3. Choose capture boundaries and screen sizes, find pages, then inspect the page
   list before capturing. Advanced configuration remains available but does not
   dominate the first screen.
4. Capture the reviewed inventory. Explain progress, interruptions and failures
   without claiming unknown coverage is complete.
5. Inspect screenshots and coverage, then explicitly save the baseline. Saving
   project settings alone never visits the website or approves evidence.

## Returning to a project

Open its workspace rather than its settings. Project context stays visible and
project switching preserves destination and protects unsaved settings. Check for
changes against the identified baseline and environment; comparisons revisit the
fixed baseline inventory, not a freshly discovered website.

Review begins with actual coverage, changed results and failed/non-comparable
targets. A searchable result queue sits beside a large, untinted comparison
viewer. Before/after origins, screen size, warnings and approval consequences
remain visible. Sensitivity, ignored areas and their revisions remain available
without turning the default screen into a wall of expert controls.

Approving selected compatible screenshots requires an impact preview and explicit
confirmation. It creates a new baseline version; other references and previous
versions remain. Failed or missing evidence cannot become an approved reference.
Replacing the entire baseline is a separate deliberate workflow.

## History and sharing

Distinguish saved baseline versions from capture/check runs. Explain the active
reference and composite versions in ordinary language. Preserve ZIP privacy
previews, recipients' separate login setup, storage totals, protected shared
references and deliberate deletion. Ignored areas are not pixel redaction.

## Visual direction and verification

Deep-blue project navigation, white working surfaces, sky-tinted selection,
readable system UI typography and small native-like control corners. The visual
signature is a self-labelling next safe action, not decorative charts or imagery.
The chosen illustrative HTML composition is a planning reference, not an app
screenshot; synthetic demonstration results never enter live project data.

Implement and verify ordinary and small desktop windows, keyboard focus and
mounted-control availability. GPUI renderer captures can establish visible
layout on the development host, but do not qualify OS window presentation,
real keyboard/IME input, accessibility, Windows/macOS or public-release readiness.
